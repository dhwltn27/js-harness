# 독립 검산

시작할 때 사용자에게 "지금부터 새 기능은 넣지 않습니다"라고 알린다.

## 1. 검사관 부르기
spawn_agent 1회: model `gpt-6.1-sol`, reasoning_effort `high`, fork_turns `none`. 메인 대화에 맡긴 이유 한 줄.

검사관 지시에 넣을 것:
- 과제 폴더 위치. 읽을 것은 README, 결정 기록(확인한 조건, 완료 조건), 원본 데이터, 결과 파일뿐. 구현 코드와 테스트는 열지 않고 import하지 않는다.
- 과제 파일은 고치지 않는다. 검산 스크립트와 중간 파일은 과제 폴더 밖 임시 폴더에만 만든다.
- 원본 행과 원본 값은 화면, 로그, 스크립트 출력에 내지 않는다. 건수, 행 번호, 적용한 규칙, 일치 여부만 쓴다.
- 할 일
  1. 원본에서 직접 다시 계산하는 짧은 스크립트로 완료 조건의 숫자(건수, 제외 건수, 집계값, 지표)를 구하고 결과 파일 숫자와 대조표를 만든다.
  2. 규칙이 걸리는 항목 5개를 골라(중복, 시간, 단위, 빈 값, 경계처럼 서로 다른 규칙이면 좋음) 규칙대로 직접 계산한 값과 결과 파일의 값을 스크립트 안에서 비교한다. 보이는 것은 행 번호, 적용한 규칙, 일치 여부뿐이다.
  결과 파일이 없는 과제(웹 화면, 기존 코드 수정 등)라면 README 실행 명령, 기존 테스트, API 응답이나 화면에 나오는 숫자를 대조 대상으로 삼는다.
  3. 모델이나 AI 기능 과제라면 학습에 쓴 데이터와 평가 데이터를 나눠 지표를 다시 계산하고, 보고된 수치와 비교한다.
  4. 결과를 그대로 말하고, 불일치는 원인 가설과 함께 적는다.

## 2. 재현성과 바뀐 입력 (메인)
- 결과가 매번 같아야 하는 도구라면 같은 입력으로 두 번 실행해 결과 파일 해시를 비교한다. 난수나 시각이 들어가는 결과라면 핵심 숫자가 허용 범위 안인지로 본다.
- 바뀐 입력 재실행은 빠뜨리지 않는다. 담당자가 말한 "다음 입력에서 바뀔 수 있는 것"으로, 답이 없으면 열 순서 바꾸기, 새 범주나 단위 한 줄, 다른 날짜 폴더 세 가지로 작은 합성 입력을 만들어 돌린다(예: 열 순서 바꾸기, 새 범주나 단위 한 줄, 다른 기간 파일). 조용히 틀린 값이 나오지 않고, 처리하거나 분명히 멈추는지 본다. 합성 입력은 과제 폴더 밖에 두고 제출물에 넣지 않는다.

## 3. 정리
- 대조표, 5개 항목 대조, 재현성, 바뀐 입력 결과를 결정 기록 "검증 결과"에 명령과 숫자로 남긴다.
- 불일치가 있으면 고치지 말고 사용자에게 보인다. 고치면 같은 검산을 한 번 더 돌려 짝을 남긴다.
