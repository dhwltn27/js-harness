# 검수

작업 파일을 고치지 않고 commit하지 않는다. 확인용 입력과 스크립트는 작업 폴더 밖 임시 폴더에만 만든다. 원본 행, 비밀값, 개인정보는 출력하지 않고 건수, 행 번호, 열 이름과 개인정보가 아닌 집계·계산값만 쓴다. 보안 검토는 `$cp-secure`가 맡는다.

할 일이 끝날 때는 1·2절만, 사용자가 "마감"이나 "최종"이라고 하거나 마감 모드면 1~4절을 한다. 앞서 한 검수 뒤로 바뀐 파일이 없으면 이미 한 확인은 그 결과를 다시 쓰고, 아직 하지 않은 확인만 새로 한다.

## 1. 실행
1. README 실행 명령을 그대로 실행한다. 출력 위치를 받는 명령이면 출력만 임시 폴더로 보낸다. 종료 코드, 출력 파일이 생겼는지, 출력 건수를 적는다.
2. 전체 테스트를 실행한다: 실행 개수, 통과, 실패, 건너뜀. 0개면 "테스트 없음"으로 적고 통과로 치지 않는다. 계산 규칙의 경계 사례(빈 입력, 빈 값, 분모 0, 날짜 경계, 새 범주, 동점, 짝 없는 키) 중 과제에 해당하는 것이 테스트에 들어 있는지 보고, 빠진 것을 적는다.
3. 같은 입력으로 한 번 더 실행한다. 결과가 매번 같아야 하는 도구면 출력 파일 해시를, 아니면 핵심 숫자를 비교한다.
4. 바뀐 입력 하나로 실행한다. 요청자가 말한 "다음에 바뀔 수 있는 것"을 쓰고, 답이 없으면 빈 파일, 없는 경로, 열 순서 바꾸기, 새 범주 한 줄 중 과제에 맞는 것을 쓴다. 조용히 틀린 값을 내지 않고 처리하거나 분명한 오류로 멈추는지 본다.
5. 웹 서버라면 정해진 주소와 포트, 주요 경로의 응답 코드, 디버그 모드가 꺼져 있는지, 화면과 API의 숫자가 결과 파일과 같은지 본다.

## 2. 숫자 대조
1. 건수 보존: 입력 행 수 = 남긴 행 수 + 제외한 행 수(+ 따로 둔 행 수). 집계 결과라면 출력 행 수가 아니라 집계에 들어간 원본 행 수의 합으로 맞추고, 파일을 이은 뒤 행 수가 기록한 예상 관계와 제외 규칙에 맞는지 따로 본다. 맞지 않으면 문제로 적는다.
2. 완료 조건의 핵심 숫자 2~3개를 구현 코드를 쓰지 않고 원본에서 직접 다시 계산해 결과와 대조한다. 같은 집계 함수를 다시 부르거나 구현 코드를 복사한 계산은 독립 검산이 아니다. 결과값 / 검산값 / 차이 / 판정을 표로 보이고, 다른 계산 경로가 없으면 "확인 못 함"으로 적는다.
3. 한 대상·한 기간(예: 장비 하나의 하루, 고객 하나의 한 달)을 골라 분자와 분모를 이루는 구간이나 건별 계산표를 계산한 값으로 보이고, 사용자가 손으로 대조할 숫자 1~2개를 짚는다. 사람 정보는 넣지 않고 원본 행을 그대로 출력하지 않는다.
4. 마감 때는 이 절을 새 검사관에게 맡긴다. 검사관은 README, 결정 기록, 원본 데이터, 결과 파일만 읽고 구현 코드와 테스트는 열지 않는다. 규칙이 걸리는 항목 5개(중복, 시간, 단위, 빈 값, 경계처럼 서로 다른 규칙)를 직접 계산해 결과와 비교하고, 행 번호, 적용한 규칙, 일치 여부만 보인다.

## 3. 요구 충족 (마감)
1. README 필수 요구와 결정 기록의 확인한 조건마다 통과 / 실패 / 확인 못 함 / 해당 없음(이유), 근거 파일:줄. 일부만 채웠으면 실패로 두고 빠진 부분을 적는다. 화면이나 API 항목은 사용자가 확인했다는 기록([사용자 확인])이 있는지도 본다.
2. 제출 형식: README가 요구한 파일명, 위치, 형식, 필수 섹션과 키가 실제로 있는지.
3. 문서와 실제의 일치: 결정 기록의 결정, 수치, 검증 결과가 지금 코드와 결과와 같은지.
4. 정리 상태: 제출할 파일이 저장소에 있는지, 임시 파일이 섞이지 않았는지. 비밀 파일과 개인정보는 `$cp-secure` 결과를 쓴다.

## 4. 설명 준비 (마감)
- 이 결과물을 설명할 때 나올 만한 질문(결정 이유, 구조·데이터 흐름, 실패·한계)을 뽑고, 질문마다 답의 근거가 되는 파일:함수와 숫자를 붙인다.
- 질문은 대화에만 보이고 제출물에 넣지 않는다.
- 답 틀: [결론] [근거: 파일·숫자] [확인: 실행 결과] [한계].

## 출력
표 하나: 항목 / 실행한 명령 / 결과 숫자 / 판정(통과, 실패, 확인 못 함, 해당 없음).
- 실패마다 등급(급함: 비밀 노출·원본 손상 / 높음: 핵심 숫자 오류·필수 기능 실패·업무 규칙 위반 / 보통: 일부 예외·재현성 / 낮음: 모양·선택 개선), 영향(결과가 틀리는가, 기록만 빠졌는가), 고칠 방법을 붙이고 사용자가 고르게 한다: 지금 고칠 것 / 결정 기록 "남은 한계"에 적을 것.
- 실행되지 않은 확인은 "확인 못 함"과 원인으로 적고 통과로 치지 않는다. "해당 없음"은 이유를 적는다.
