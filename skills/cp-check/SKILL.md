# 실행·보안 검토

작업 파일을 고치지 않고 commit하지 않는다. 확인용 입력과 스크립트는 작업 폴더 밖 임시 폴더에만 만든다. 비밀값, 개인정보, 원본 행은 출력하지 않고 파일 위치, 열 이름, 건수만 쓴다. `.env` 같은 비밀 파일은 열지 않는다.

## 1. 실행
1. README 실행 명령을 그대로 실행한다. 출력 위치를 받는 명령이면 출력만 임시 폴더로 보낸다. 종료 코드, 출력 파일이 생겼는지, 출력 건수를 적는다.
2. 전체 테스트를 실행한다: 실행 개수, 통과, 실패, 건너뜀. 0개면 "테스트 없음"으로 적고 통과로 치지 않는다.
3. 같은 입력으로 한 번 더 실행한다. 결과가 매번 같아야 하는 도구면 출력 파일 해시를, 아니면 핵심 숫자를 비교한다.
4. 잘못된 입력 하나(빈 파일, 없는 경로, 모르는 열이나 형식 중 과제에 맞는 것)로 실행해, 조용히 틀린 결과를 내지 않고 분명한 오류로 멈추는지 본다.
5. 웹 서버라면 `0.0.0.0` 바인딩, 포트, 주요 경로의 응답 코드를 확인한다.

## 2. 보안
1. 비밀 파일 후보(`.env*` 단 `.env.example` 제외, `*.key`, `*.pem`, `credentials*`)가 git에 추적되는지, 예전 기록에 있는지. `git ls-files`, `git log --all --name-only --format=`로 이름만 본다.
2. 코드와 설정에 박힌 비밀값 후보: `password`, `secret`, `token`, `api_key` 같은 이름 옆에 실제 값이 대입된 곳, 긴 무작위 문자열. 파일:줄만 쓰고, 환경변수 이름만 있는 줄은 뺀다.
3. 출력 파일, 로그, 오류 메시지에 개인정보나 원본 행이 들어가는지. 열 이름과 건수만 쓴다.

## 출력
표 하나: 항목 / 실행한 명령 / 결과 숫자 / 판정(정상, 문제, 확인 못 함).
- 문제마다 영향 한 줄과 고칠 방법 제안을 붙인다. 고칠지는 사용자가 정한다.
- 보안 문제가 있으면 `$cp-secure`로 처리할 수 있다고 알린다.
- 실행되지 않은 확인은 "확인 못 함"과 원인으로 적고 정상으로 치지 않는다.
