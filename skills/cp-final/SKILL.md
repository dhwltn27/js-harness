# 최종 점검

메인이 직접 점검한다. 이 단계에서는 파일을 고치지 않고 보고만 한다.

## 1. 점검표
1. 요구 충족: README 필수 요구와 결정 기록의 확인한 조건마다 충족 / 부분 / 미충족, 근거 파일:줄.
2. 실행과 보안: `$cp-check` 결과를 쓴다. 아직 안 했거나 그 뒤 파일이 바뀌었으면 `$cp-check` 순서대로 다시 확인한다.
3. 제출 형식: README가 요구한 파일명, 위치, 형식, 필수 항목이 실제로 있는지.
4. 문서와 실제의 일치: 결정 기록의 결정, 수치, 검증 결과가 지금 코드와 결과와 같은지. 다른 곳을 목록으로.
5. 정리 상태: 제출할 파일이 저장소에 있는지, 제출물에 섞이면 안 되는 임시 파일이나 비밀 파일이 있는지.
6. 앞 단계의 독립 검산 결과가 지금도 유효한지(그 뒤 바뀐 파일이 있는지) 확인한다. 유효하면 그대로 쓰고, 없거나 바뀐 파일 때문에 무효가 됐으면 영향받는 확인만 다시 한다. 시간이 없으면 "검증 안 됨"으로 남은 한계에 적는다.

## 2. 결과 처리
- 표를 그대로 보인다.
- 미충족·불일치마다 영향(결과가 틀리는가, 기록만 빠졌는가), 고치는 데 걸릴 시간, 고친 뒤 다시 확인할 수 있는지를 적고 사용자에게 고르게 한다: 지금 고칠 것 / 결정 기록 "남은 한계"에 적을 것.
- 고쳤으면 해당 확인 명령을 다시 돌려 짝을 남기고, 확인을 통과하면 commit한다.

## 3. 설명 준비
- 이 제출물로 나올 만한 질문 6개: 결정 이유 2개, 구조·데이터 흐름 2개, 실패·한계 2개. 질문마다 답의 근거가 되는 파일:함수와 숫자.
- 질문은 대화에만 보이고 제출물에 넣지 않는다.
- 마지막 안내: "마무리 전에 AI 없이 결정 기록과 근거 위치를 읽어 보세요. 답 틀: [결론] [근거: 파일·숫자] [확인: 실행 결과] [한계]."
