# 과제 시작 분석

사용자가 먼저 쓴 "내 방향"(목표, 완료 기준, 모르는 것)이 있으면 그 내용을 출발점으로 삼고, 다른 점이 보이면 짚는다. 완료 기준이 없으면 출력 끝에서 사용자에게 완료 기준을 한 줄로 정해 달라고 묻는다.

## 하지 않는 것
- 과제 파일, 커밋을 만들거나 바꾸지 않는다. 훑어보는 스크립트는 임시 폴더에서만 돌린다.
- 원본 데이터 값도 출력하지 않는다. 이름, 건수, 형식 패턴만 쓴다.

## 순서
1. README와 과제 폴더 구조를 읽고 과제 유형을 정한다(분석·보고 / 정제 파이프라인 / 예측 모델 / 웹·API / AI 기능 / 기존 코드 수정, 겹칠 수 있음). 결과물 약속(제출 파일명, 형식, 실행 명령, 기존 테스트 명령)을 찾는다.
2. 입력 형식을 먼저 확인한다(표, JSON, 텍스트, 로그, 코드 등). 형식에 맞는 것만 센다. 표라면 행 수, 열, 시간·단위·표기 특이점, 빈 값, 중복을, 텍스트라면 건수와 길이, 언어, 개인정보가 섞였는지를 본다.
3. `references/traps.md`의 공통 절과 해당 유형 절을 읽고 실제 신호가 있는 함정만 고른다.
4. 보안 위치: 비밀 파일 존재와 git 추적 여부(`git ls-files`, `git log --all --name-only --format=`로 이름만), 개인정보로 보이는 열이나 필드.
5. 실행 환경(Python, Node 등)이 실제로 도는지 짧은 명령으로 한 번 확인한다. 안 되면 원인과 대안을 적는다.

## 출력 (그다음 멈춤)
- 한 줄 요약: 과제 유형, 만들 결과물, 실행 명령
- 요구사항: [필수·선택]과 확인 방법. 필수 위주로 짧게
- 입력 특이점과 함정 후보: 실제로 본 신호와 건수, 결과에 미칠 영향
- 보안 위치: 위치 / 종류 / git 추적 여부
- 담당자 질문 후보: 결과에 영향이 큰 순서로, 아직 README로 답이 안 되는 것만. 질문마다 이유 한 줄. 첫 번째는 항상 이 질문이다.
  - 다음에 들어올 데이터는 무엇이 바뀔 수 있나요? (열 순서, 단위, 새 값, 기간)
  - 아래 질문은 README가 답하지 않았으면 넣는다: 결과는 누가 보나요? 개인정보를 넣어도 되나요?

마지막 줄: "담당자에게 하나씩 물어보세요. 답을 받으면 '담당자 답: …'으로 알려 주세요."
