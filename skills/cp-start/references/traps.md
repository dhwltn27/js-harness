# 함정 목록

데이터 과제라면 분야와 상관없이 공통 절을 먼저 보고, 과제 유형에 맞는 절을 하나 더 본다. 함정마다 데이터에서 신호를 세고, 정책이 필요한 것은 담당자 질문으로 넘긴다.

## 공통
- 중복: 완전히 같은 행, 같은 키인데 값만 다른 행
- 시간: 시간대 섞임(`Z`, `+09:00`, 표기 없음), 날짜 형식 섞임, 문자열 정렬로 틀어지는 순서, 업무 날짜 경계(자정이 아닌 경우), 기간 밖·경계 걸침
- 표기: 같은 대상의 다른 표기(대소문자, 공백, 하이픈, 약어, 오타), 범주 이름 변형
- 단위와 통화: 행마다 다른 단위, 단위 열 존재 여부, 환산 시점과 반올림. 단위 표기가 없으면 값 범위로 추정하고 근거를 남긴다(값을 지우지 않는다)
- 빈 값: 빈칸, `NA`, `null`, `-1`, `-999`, `0`처럼 여러 표기. 불가능한 값(음수 수량·시간, 범위 밖)
- 집계: 분모 정의, 비율의 평균과 합계 기준 비율의 차이, 동점 처리, 상위 N 기준
- 조인: 키가 안 맞아 빠지는 행, 1:N 조인으로 늘어나는 행
- 사람과 비밀: 이름·연락처·사번·이메일 열, 자유 텍스트 속 개인정보, 커밋된 비밀 파일
- 다음 실행: 새 범주, 새 단위, 열 순서·이름 변경, 다른 기간 파일. 조용히 틀린 값이 나오는지

## A. 분석·보고
- 순위나 판단 기준(건수, 금액, 시간, 비율), 제외 대상
- 보고서 독자와 공유 범위, 결론마다 근거 숫자

## B. 정제·변환 파이프라인
- 다시 돌리는 도구라면 같은 입력에 같은 결과, 출력 폴더 생성
- 모르는 형식이 나오면 멈추거나 보고(조용히 넘기지 않기)
- 플래그·규칙이 겹칠 때 우선순위, 처리 건수 리포트

## C. 예측·분류·추천 모델
- 누수: 예측 시점에 없는 값, 정답에서 파생된 값. 학습 데이터에는 차 있고 예측 데이터에는 빈 열
- 검증 분할: 시간 흐름이 있으면 시간 분할, 같은 대상이 양쪽에 섞이지 않게
- 업무 지표: 정확도 대신 업무가 실제로 쓰는 지표(상위 K개 적중률, 재현율, 비용)
- 예외 규칙(항상 포함·제외), 불균형, 성능을 부풀리지 않는 보고

## D. 웹 화면·대시보드·API
- 화면에 꼭 있어야 하는 항목(숨은 기능 요구), 빈 데이터·오류 상태
- 서버는 `0.0.0.0`에 띄우고 사용자가 플랫폼 Browser 도구로 직접 눌러 확인(자동 조작 도구 금지), 화면 숫자와 계산 결과 일치
- 기존 API 계약 유지, 같은 요청 재전송, 실패·timeout 경로

## E. AI 기능 구현 (텍스트 분류, 요약, 검색, 추출)
- 개인 API 키 금지, 다른 AI 모델이나 외부 AI 서비스 연결 금지. 과제가 제공한 방식만 쓰고, 없으면 규칙 기반 방법으로 대체하고 이유를 기록
- 평가용 정답 예시로 정확도를 숫자로 확인, 잘못 나온 예시 기록. 학습에 쓴 예시와 평가 예시를 나눈다
- 입력 속 지시문(프롬프트 주입), 개인정보가 섞인 입력, 비용과 속도
- 결과가 매번 달라질 수 있으면 그 범위를 기록하고, 정확히 같은 결과를 완료 조건으로 삼지 않는다

## F. 기존 코드 수정
- 바꾸면 안 되는 것(API, 데이터 형식, 정책), 원인과 수정 범위 먼저
- 정상·실패 경로 테스트, 기존 테스트 통과 유지, 설정은 환경변수
