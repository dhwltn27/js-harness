# js-harness

Codex로 데이터 작업을 할 때 쓰는 작업 규칙과 Skill 묶음이다. 요구사항 확인, 결정 기록, 독립 검산, 보안 점검을 정해진 때에 하게 한다. 특정 분야를 가정하지 않는다.

## 설치 (Codex가 읽고 따라 한다)

이 저장소는 작업 폴더 밖(예: 홈 폴더 `~/js-harness`)에 받는다. 작업 폴더 안에 받으면 결과물에 섞인다. 받은 위치를 `HARNESS`, 작업 폴더를 `TASK`라고 한다. 설치는 여러 번 해도 결과가 같아야 한다.

1. `HARNESS/skills/` 아래 `SKILL.md`가 있는 폴더 4개를 `~/.agents/skills/`로 복사한다. 같은 이름 폴더가 이미 있으면 파일 내용을 비교해 같으면 건너뛰고, 다르면 덮어쓰지 말고 사용자에게 알린다. 과제 폴더 안에는 복사하지 않는다.
2. `TASK/AGENTS.md`가 없으면 `HARNESS/AGENTS.md`를 복사한다. 이미 있으면 바꾸지 말고, 두 문서의 겹치거나 충돌하는 줄을 보이고 사용자에게 어떻게 합칠지 묻는다. 이미 같은 내용이 들어 있으면 다시 덧붙이지 않는다.
3. 그 밖의 과제 파일은 바꾸지 않는다. `templates/DECISIONS.md`는 과제에 같은 역할의 문서가 없을 때만 나중에 쓴다.
4. 복사한 파일 목록을 보이고, 사용자에게 `/skills`로 목록을 확인하고 안 보이면 Codex를 다시 시작하라고 알린다.
5. 마지막으로 `TASK/AGENTS.md`를 읽고 이 과제에 맞지 않는 줄이 있으면 알려 준다.

Skill이 끝내 목록에 안 보이면 설치를 건너뛴다. `AGENTS.md` 규칙에 따라 Codex가 이 저장소의 `skills/<이름>/SKILL.md`를 직접 읽어 같은 순서로 진행한다.

## 구성

| 파일 | 언제 | 하는 일 |
|---|---|---|
| `AGENTS.md` | 항상 | 결정 출처, 범위, 검증, 보안, 역할, 저장 규칙 |
| `$cp-start` | 시작 | 과제 유형, 요구사항, 입력 특이점, 함정 후보, 보안 위치, 담당자 질문 후보 |
| `$cp-secure` | 비밀 파일이나 개인정보가 보일 때 | 추적 해제, 환경변수, 허락 범위 밖 개인정보 제거, 한계 기록 |
| `$cp-recount` | 마감 전 | 원본에서 다시 계산, 5개 항목 직접 대조, 바뀐 입력 재실행 |
| `$cp-final` | 마무리 전 | 최종 점검표, 결과를 설명할 때 받을 질문 6개 |
| `templates/DECISIONS.md` | 질문이 끝난 뒤 | 결정 기록 틀(과제에 없을 때만) |

담당자 답 반영, 계획, 작업 진행, 오류 반복, 웹 서버 확인은 Skill 없이 `AGENTS.md` 규칙으로 처리한다. 목표와 제약, 작업 지시는 사용자가 직접 쓴다.

## 역할

- 메인: 사용자와 대화하며 분석, 계획, 구현, 확인, 저장을 맡는다.
- 일꾼(선택): 사용자가 모델과 추론 단계를 지정해 맡기라고 할 때만 부른다.
- 검사관: `gpt-6.1-sol` high 서브에이전트. 매번 새로, 대화 기록 없이 부르고 작업 파일을 고치지 않는다.
